# 긱뉴스(GeekNews) 게시 초안 — 3D 지도·공개 MCP 서버 (2026-11-10)

alvin.ing 기술 글 두 편을 긱뉴스에 올리기 위한 제목·본문 초안이다. 긱뉴스는 제품 홍보보다 **보편적인 문제와 트레이드오프**를 앞에 두는 글이 반응이 좋으므로, 서비스 이름은 본문 끝에 한 번만 둔다.

## 올리기 전 확인

- 두 글을 **같은 날 연달아 올리지 않는다.** 하루 이상 간격을 둔다(3D 지도 글 먼저 권장 — 대상 독자가 더 넓다).
- 자기 글이므로 제목 앞에 `Show GN:`을 붙이는 형식도 가능하다. 다만 Show GN은 보통 제품·프로젝트 소개용이라, 글 자체를 공유할 때는 일반 글로 올리고 본문 첫 줄에 작성자임을 밝힌다.
- 링크는 canonical URL을 쓴다(끝 슬래시 없음).
- 본문은 긱뉴스 관례대로 `~함`·`~임` 요약체 불릿으로 쓴다. 숫자는 글에 적힌 값만 쓴다.
- 댓글에서 받을 만한 질문: 브이월드 상업적 이용 조건, OSM 데이터 품질, AI가 쓴 코드의 유지보수, MCP 서버 비용·남용. 답은 글의 해당 절로 연결한다.

## 1. 3D 지도 글

- **URL:** https://alvin.ing/blog/apartment-3d-map-open-data-stack

### 제목 후보

1. AI 시대, 누구나 3D 지도를 만들 수 있다 — 유료 SDK 없이 공개 데이터와 오픈소스로 만든 11일 **(권장)**
2. 유료 지도 SDK 없이 1인 개발로 3D 지도를 사흘 만에 출시한 방법
3. 브이월드 + OSM + MapLibre로 만든 아파트 3D 지도, AI 에이전트와 함께 11일

### 본문

```text
1인 개발로 아파트 주변 3D 지도를 만들며 정리한 글입니다. (작성자 본인)

- 유료 지도·3D·지오코딩 서비스와 외부 3D 모델 파일 없이 만든 3D 지도. 10월 31일 프로토타입, 사흘 뒤 출시, 이후 8일간 다듬음
- 3D 지도의 세 가지 벽(데이터·렌더러·코드 작성 비용)이 동시에 낮아짐
  - 데이터: 브이월드 건물 외곽선·지오코더, 건축물대장 높이, OpenStreetMap 국내 추출본, Valhalla 도보 경로
  - 렌더러: MapLibre GL JS + OpenFreeMap 무료 타일, fill-extrusion으로 건물을 세움
  - 코드: 지도 관련 커밋 577개 중 458개(약 79%)에 AI 코딩 에이전트가 작성자·공동 작성자로 기록됨
- API 키 없이 HTML 파일 하나로 3D 건물 지도를 띄우는 시작 코드와 실행 화면 포함
- AI가 잘한 일: 그림자·광선 기하 계산, 3D 파일 없이 코드로 그리는 모형 수십 종, API 파싱·재시도, 테스트 260여 개
- 사람이 끝까지 정한 일
  - 원칙: 유료 서비스·외부 모델 금지 같은 제약을 먼저 정해야 AI가 편한 길로 빠지지 않음
  - 신뢰: 높이마다 출처를 붙이고, 일조 계산에는 직접 확인된 높이만 사용. 이 경계는 프롬프트가 아니라 데이터 구조로 강제
  - 측정: 느린 원인은 에셋이 아니라 코드 습관(늦은 자료로 지도 전체 재생성, 효과마다 rAF 루프, 프레임마다 데이터 기반 페인트 값 변경 등). 실기기 측정 전엔 아무도 몰랐음
- 공개 데이터 예의: ODbL 출처 표기, 공용 Overpass·Valhalla 서버는 소량만, 반복 질의는 추출본으로
- 결론: 질문이 "팀과 예산이 있는가"에서 "어떤 데이터를 믿고, 무엇을 보여 주지 않으며, 실제로 빠른가"로 바뀜
```

## 2. 공개 MCP 서버 글

- **URL:** https://alvin.ing/blog/public-mcp-server-design

### 제목 후보

1. 로그인 없는 공개 MCP 서버를 ChatGPT 공식 플러그인까지 — 한 달 운영하며 정한 7가지 경계 **(권장)**
2. 인증 없는 MCP 서버, 권한은 무엇으로 지킬까: 공개 MCP 한 달 운영기
3. annotation은 권한 검사가 아니다 — 공개 MCP 서버 설계에서 배운 것

### 본문

```text
인증 없이 누구나 연결하는 공개 MCP 서버를 Cloudflare Workers로 만들고 ChatGPT 공식 플러그인으로 공개하기까지 정리한 글입니다. (작성자 본인)

- 10월 9일 도구 18개로 첫 배포, 지금은 23개(조회 22·자료 준비 1). stateless Streamable HTTP라 curl 한 줄로 tools/list 확인 가능
- 인증이 없으니 "누가"가 아니라 "무엇을"로 권한을 정함
  - 비로그인 공유 화면에 이미 보이는 값만 반환. 회원·관리자 기능은 막는 대신 도구를 아예 안 만듦
  - 공개 ID는 권한 토큰이 아님
- annotation(readOnlyHint 등)은 호스트용 힌트일 뿐 권한 검사가 아님. 읽기 전용 도구도 캐시·집계는 씀
  - 호스트마다 표시명 읽는 위치가 달라 title과 annotations.title을 같은 값으로 이중 기재
- "사용자 확인 후 실행"은 서버가 보장 못 함. 보장 가능한 것(범위·동시성)과 안내만 가능한 것을 문서에서 분리
- 업무 실패는 isError + 고정 사유 코드 11종 + 다음 호출에 필요한 값만. 프로토콜 오류와 섞지 않음
- 숫자를 만들 수 없으면 만들지 않고 이유를 돌려줌(fail-closed). 금리 가정은 증감폭이 아닌 절대값으로 받도록 스키마에 명시
- 시행착오
  - 결과 카드 10종 → 2종으로 정리. 호스트가 리소스 URI를 캐시 키로 써서 옛 URI를 지우자 이전 대화에서 오류 → 옛 URI는 호환 리소스로 유지
  - 응답 방식 JSON → SSE 자동 선택 → 다시 JSON 고정. 호출 중 알림을 안 쓰는 짧은 조회엔 예측 가능성이 더 중요
  - 브라우저 디렉터리 클라이언트의 OPTIONS 405 → CORS 추가. 단, CORS는 보안이 아님
- IP별 호출 제한은 개인 쿼터가 아님. 요청은 사용자 기기가 아니라 AI 호스트 서버에서 옴
- 디렉터리 등록: 제출·심사·승인·게시는 서로 다른 단계
```
