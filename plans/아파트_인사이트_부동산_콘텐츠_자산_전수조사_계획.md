# 아파트 인사이트 부동산 콘텐츠 자산 전수조사 계획

> **목표:** `apt-insights/docs/`의 모든 문서를 하나씩 확인해, 실제 문서가 뒷받침하는 부동산·아파트 콘텐츠와 기술 콘텐츠를 최대한 추출하고 블로그 유입 및 아파트 인사이트 앱 전환에 사용할 수 있는 실행 백로그로 정리한다.
>
> **중요:** 이 문서는 콘텐츠 목록 자체가 아니라, 콘텐츠 목록을 신뢰성 있게 만드는 실행 계획이다. 계획 완료 전까지 문서에 없는 사실·수치·사례·성과를 제목이나 본문에 추가하지 않는다.

## Goal

부동산·아파트에 관한 현실적인 검색 콘텐츠를 지속 생산해 다음 흐름을 만든다.

`부동산 검색 질문 → 아파트 인사이트 블로그 유입 → 관련 글 탐색 → 앱 진입 → 아파트 등록 → 개인화 분석·시뮬레이션·보유세 계산·알림 사용`

부동산 콘텐츠가 1차 성장 축이고, 1인 개발·AI 협업·데이터·운영 기술 콘텐츠는 개발자·B2B·기술 커뮤니티 유입을 위한 2차 성장 축이다.

## 파일명 규칙

이 계획에서 새로 만드는 문서 파일명에는 공백을 사용하지 않는다. 공백이 필요한 경우 `_`로 대체한다. 기존 저장소의 파일명은 이번 계획의 범위를 벗어나므로 별도 마이그레이션 승인 없이 일괄 변경하지 않는다.

## 블로그 채널 구조와 신규 섹션 판단

현재 사이트의 상단 구조는 `Research · Blog · GitHub`다. 이번 전수조사는 기존 메뉴를 바로 늘리는 작업이 아니라, 실제로 발행할 수 있는 콘텐츠 자산을 확인한 뒤 채널을 확장하는 순서로 진행한다.

| 채널 | 역할 | 주 콘텐츠 | 전환·활용 방식 |
|---|---|---|---|
| `Research` | 근거와 연구 맥락 | 데이터 해석, 모델·검증 원칙, 연구 노트 | 신뢰 형성. 내부 구현 세부는 제외 |
| `Blog` | 검색·공유 유입 | 부동산 실수요 질문, 금융·세금, 사용법, 기술 회고 | 글별로 아파트 인사이트 앱 행동 연결 |
| `GitHub` | 실행 가능한 코드·변경 이력 | 공개 코드, 재현 가능한 예제, 기술 문서 | 개발자 신뢰·기술 글의 보조 근거 |
| `Real Estate` 검토 | 부동산 검색 허브 | 아파트, 매매·전세, 분양, 지역, 정책, 세금 | 가장 직접적인 앱 유입 채널 |

### `Finance`보다 `Real Estate`를 우선 검토하는 이유

부동산의 영어 표현은 `real estate`다. `Finance`는 주식·투자·보험·개인 재무까지 포함할 수 있는 더 넓은 말이므로, 현재 서비스의 핵심인 아파트 콘텐츠를 담는 새 상단 메뉴명으로는 `Real Estate`가 더 정확하다.

금융 주제를 별도로 운영할 때는 다음처럼 범위를 제한한다.

- `Real Estate`: 아파트 매매·전세·분양·공급·지역·정책·보유 비용
- `Finance`: 금리·대출·가계 현금흐름·세금·주거 금융처럼 부동산 의사결정에 직접 연결되는 주제
- 주식·코인·보험 등 아파트와 직접 연결되지 않는 금융 주제는 이번 계획의 범위에 넣지 않는다.

따라서 1차 권고안은 `Research · Real Estate · Blog · GitHub`이며, `Finance`는 전수조사 결과 금융 콘텐츠가 독립적인 검색 의도와 지속 가능한 근거를 확보했을 때 `Real Estate`의 하위 분류 또는 별도 채널로 결정한다. 메뉴 추가 구현은 콘텐츠 후보·발행 빈도·앱 CTA가 확인된 뒤 별도 작업으로 진행한다.

## 기준과 범위

### 조사 대상

콘텐츠 원천은 이 계획이 있는 `playground` 저장소가 아니라 인접한 `apt-insights` 저장소의 `docs/`다. 따라서 모든 출처 경로는 `../apt-insights/docs/`를 기준으로 기록한다.

현재 확인된 조사 범위는 다음과 같다.

| 영역 | 문서 수 | 조사 원칙 |
|---|---:|---|
| 문서 루트·아키텍처·가이드·사업·모바일·이력 | 약 80개 | 사용자 가치·서비스 설명·운영 원칙 추출 |
| `../apt-insights/docs/reports/` | 143개 | 검증·진단·릴리즈·실시간 예측·1인 개발 사례 추출 |
| `../apt-insights/docs/superpowers/plans/`·`specs/` | 약 170개 | 기능 의도·문제·설계 선택 추출, 구현 완료 여부 별도 확인 |
| `../apt-insights/docs/reference/` | 1개 CSV | 데이터 사전·지역명·공개 콘텐츠 활용 가능성 확인 |
| 합계 | 현재 기준 391개 | 파일별 조사 행을 남겨 누락을 방지 |

파일 수는 문서 추가·삭제에 따라 바뀔 수 있다. 조사를 시작할 때 `rg --files docs` 결과를 다시 고정하고, 조사 종료 시 파일 수와 누락 파일을 재검증한다.

### 포함할 문서 유형

- `../apt-insights/docs/README.md`, `INDEX.md`, `QUICK_START.md`: 전체 서비스와 문서 구조의 정본
- `../apt-insights/docs/FEATURES.md`, `FACTORS.md`, `ECOS_FACTOR_MAPPING.md`: 실제 사용자 기능과 데이터·가중 팩터
- `../apt-insights/docs/architecture/`: 예측 원리, 시나리오, 실시간 추세, 비용·확장 구조
- `../apt-insights/docs/guide/`, `operations/`: 사용자 흐름, 실거래 갱신, 알림, 배치, 복구, 비용 운영
- `../apt-insights/docs/business/`, `android/`, `ios/`: 앱 가치, 출시, 스토어, 모바일 기능
- `../apt-insights/docs/history/`, `roadmap/`: 모델·서비스 변화와 개선 과정
- `../apt-insights/docs/reports/`: 검증·감사·성능·운영·릴리즈·1인 개발 증거
- `../apt-insights/docs/superpowers/plans/`, `specs/`: 기능을 만든 문제·제약·설계·실패·결정 기록
- `../apt-insights/docs/archive/`: 과거 사례로만 사용할 수 있는 문서. 현재 기능으로 재사용하지 않음

### 조사에서 제외하지 않되 발행은 제한할 영역

문서 전체를 읽되, 모든 내용을 공개 콘텐츠로 전환하지 않는다. 다음은 내부 참고로만 분류한다.

- 아파트 내부 가격대·기간별 분류 체계와 그 파생 정보
- 내부 모델 계수·상수·임계값·보정 순서·세부 평가 단위
- 학습·검증 표본 구성과 내부 성능 분할 정보
- 데이터베이스 구조·필드·캐시 키·큐 구성·관리자 경로·내부 라우트
- 내부 프롬프트·모델 설정·비용 한도·보안·복구·롤백 상세
- 테스트용 단지 목록이나 내부 표본을 통한 구조 역추정 정보

이 정보는 문서 조사 때 “내부 전용/콘텐츠 금지”로 기록하되, 블로그 제목·본문·메타·FAQ·CTA·이미지 설명에는 넣지 않는다.

## Source of Truth 및 문서 상태 규칙

### 현재 상태와 역사 상태 분리

1. 현재 기능·서비스 상태: `docs/README.md`, `docs/FEATURES.md`, `history/SERVICE_HISTORY.md`
2. 공개 표현·면책: `docs/public-copy-terminology.md`, `docs/public-copy-checklist.md`, `AGENTS.md`
3. 현재 모델 수치: 최신 production 검증 문서와 그 인덱스
4. 계산 원리: `architecture/`의 해당 정본
5. 운영 계약: `guide/`, `operations/`의 해당 런북
6. 과거 릴리즈·구버전 검증: 역사 사례로만 사용
7. `superpowers/plans/`·`specs/`: 설계 의도와 작업 기록. 구현 완료를 의미하지 않음
8. `archive/`: 현재 상태를 설명하는 근거로 사용하지 않음

문서끼리 내용이 다르면 최신 정본의 현재 상태를 우선하고, 과거 문서는 “당시에는”이라는 역사 표기를 붙인다. 계획·설계 문서의 예정 기능을 구현 완료 기능처럼 작성하지 않는다.

### 파일별 조사 기록 필드

모든 Markdown 문서와 CSV에 대해 다음 필드를 기록한다.

| 필드 | 설명 |
|---|---|
| `source_markdown` | 다음 세션에서 다시 열어볼 정확한 출처 Markdown 경로. 후보 목록에 필수 |
| `source_type` | 정본·가이드·검증·감사·릴리즈·계획·설계·역사·아카이브·데이터 |
| `title` | 문서 제목 |
| `date_or_version` | 문서 기준일·릴리즈·모델 버전 |
| `status` | current·historical·planned·implemented·deprecated·unknown |
| `explicit_topics` | 문서에 실제로 적힌 주제·문제·기능 |
| `evidence_sections` | 주제를 뽑은 제목·섹션 |
| `candidate_titles` | 출처에 근거한 블로그 제목 후보 |
| `audience` | 실수요자·보유자·지역 탐색자·개발자·B2B 등 |
| `search_intent` | 정보형·비교형·문제 해결형·사용법형·기술 회고형 |
| `app_bridge` | 연결할 앱 화면·행동. 없으면 없음으로 기록 |
| `freshness` | 상시·월간·정책 변경 시·릴리즈 시·역사 전용 |
| `public_safety` | 공개 가능·개념만 공개·기술 채널 한정·발행 금지 |
| `notes` | 충돌·중복·구현 여부·추가 확인 필요 사항 |

## 콘텐츠 추출 원칙

### 현실성 검증 규칙

콘텐츠 후보는 다음 중 하나 이상의 직접 근거가 있어야 한다.

- 문서의 제목·목차·본문에 명시된 사용자 문제
- 실제 구현된 기능 목록 또는 현재 서비스 이력
- 실제 검증·감사·운영 결과에 적힌 관찰·문제·수정
- 실제 릴리즈 노트에 기록된 변경
- 계획·설계 문서에 명시된 문제·제약·결정. 단, 계획 상태를 제목에 표시

다음은 콘텐츠 후보로 만들지 않는다.

- 문서에 없는 시장 전망·지역 평가·성능 수치
- 코드나 데이터 확인 없이 만든 “아파트별 예상 가격”
- 계획 문서의 기능을 이미 출시된 것처럼 표현한 글
- 역사 수치를 현재 성능처럼 재사용한 글
- 내부 구조를 한국어로 바꿔 우회한 글

### 문서 1개에서 뽑는 콘텐츠 단위

각 문서에서 무조건 많은 제목을 만들지 않는다. 실제로 의미가 있는 단위만 다음 유형으로 분리한다.

1. **개념 설명:** 독자가 이해해야 할 개념 1개
2. **문제 해결:** 사용자가 겪는 문제와 해결 순서
3. **비교:** 두 개념·선택지·기간·데이터 상태의 차이
4. **사례·회고:** 실제 변경·장애·검증·실패에 대한 기록
5. **사용법:** 실제 화면에서 수행하는 행동
6. **데이터 읽기:** 공개 데이터·거래·범위·오차를 해석하는 법
7. **기술 설계:** 문제·제약·트레이드오프·검증 중심의 기술 글
8. **릴리즈·업데이트:** 실제 구현된 변화와 사용자 영향

문서의 한 섹션이 한 문장으로 끝나는 경우에는 별도 글로 부풀리지 않고 관련 주제의 FAQ나 묶음 글에 편입한다.

## 콘텐츠 분류 체계

### A. 부동산 검색 유입 콘텐츠

- 아파트 실거래·시세 읽기
- 매매·전세·이사 시점
- 신축·분양·거래 부족 단지
- 재건축·재개발·교통 호재
- 학군·직주근접·생활 인프라
- 공급·인구·전세가율
- 금리·환율·유가·가계부채·건설비
- 세금·보유 조건·정책 변화
- 지역별·단지별 비교와 데이터 해석

### B. 신뢰·전환 콘텐츠

- 예측 범위와 조건부 기본 경로
- 평균 절대 오차와 과거 검증 읽기
- 실거래 표본·신뢰도·거래 데이터 한계

- 공개 데이터 출처와 서비스 이용 한계

### C. 기술 커뮤니티 콘텐츠

- 1인 개발 작업 리듬과 문서화
- AI 에이전트 협업과 검증 경계
- 부동산 데이터 수집·정합성·신선도
- 예측 서비스의 검증·회귀 방지·관측성
- 서버리스·큐·캐시·비용 최적화

- 실패한 시도와 폐기 결정

### D. 발행 금지 또는 내부 전용 콘텐츠

내부 모델 분류·세부 계수·검증 표본·운영 키·관리자 경로·프롬프트·보안·비용 한도 등은 제목 후보로 만들지 않고 조사 기록에서만 금지 상태로 남긴다.

각 글의 CTA는 하나를 기본으로 하고, 글의 질문에 답한 뒤 같은 문제를 개인화할 수 있는 앱 행동으로 연결한다.

## 예상 결과물의 우선순위

1. **상시 검색형:** 아파트 실거래·전세·시세·금리·세금·지역·신축 등
2. **시의성 검색형:** 정책·금리·세제·시장 변화가 실제 문서 근거와 함께 갱신될 때
3. **앱 전환형:** 아파트 등록·시뮬레이션·보유세·알림·예측 이력 사용법
4. **신뢰 형성형:** 데이터 품질·검증·오차·불확실성 설명
5. **기술 커뮤니티형:** 1인 개발·AI 협업·서버리스·데이터 운영·실패 회고

위 순서는 콘텐츠 수가 아니라 사업 목적에 따른 발행 우선순위다. 최종 제목 수와 발행 순서는 전수조사 결과와 공개 가능 판정이 끝난 뒤 확정한다.
